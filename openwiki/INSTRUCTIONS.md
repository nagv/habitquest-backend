The rest you run on your own machine, because it needs Node.js and an LLM key, and this session has neither.## In the repo (done)- **`openwiki/INSTRUCTIONS.md`** is the brief OpenWiki follows on every run, and `--init` doesn't overwrite it. It asks for 13 pages, each citing file paths. Two of them are mandatory and must be exhaustive:  - **Dependencies:** every direct dependency from `pyproject.toml`, why it's used and where it's imported, plus dev and Node tools.  - **Network calls and egress:** every outbound connection (Postgres, JWKS, Ollama, Gemini, the OpenAI-compatible endpoint, scripts, build), which process makes it and the setting that controls it. Then a per-deployment allowlist of what must be reachable.  The brief lists the known calls and tells OpenWiki which code patterns to search, so newly added calls get picked up too.- **`.openwikiignore`** excludes lockfiles, build and coverage output, `.env` files and the historical implementation plans.## On your machine (Node.js 22.22+)1. Install it:   ```bash   npm install -g openwiki   ```2. Configure your Nebius key for OpenWiki in `~/.openwiki/.env`. This is OpenWiki's own setting and is separate from the app's Render variables:   ```   OPENWIKI_PROVIDER=openai-compatible   OPENAI_COMPATIBLE_BASE_URL=<your Nebius OpenAI-compatible endpoint>   OPENAI_COMPATIBLE_API_KEY=<your Nebius key>   OPENWIKI_MODEL_ID=<a Nebius model id>   ```   Pick a strong long-context model, since it reads the whole repo.3. In the repo, on a new branch from `main` with `openwiki/INSTRUCTIONS.md` merged in, run:   ```bash   openwiki --init   ```   That writes `openwiki/*.md`, `index.md`, `quickstart.md` and `log.md`, and adds an `<!-- OPENWIKI:START -->` block to `AGENTS.md`. To browse the result locally:   ```bash   openwiki visualize   ```4. Check before committing:   - the network page lists every call, with the default `fake` mode making no model calls   - all 36 endpoints are covered   - every `Settings` field appears in the configuration page   - no secret values appear anywhere   Then commit and open a PR.## Keeping it updated (GitHub Actions)1. Copy `examples/openwiki-update.yml` from the OpenWiki repo to `.github/workflows/openwiki-update.yml`. It runs daily at 08:00 UTC, or on demand, and opens a "docs: update OpenWiki" PR from the `openwiki/update` branch.2. The example uses OpenRouter. Change its environment to `OPENWIKI_PROVIDER: openai-compatible` and set the base URL and model id.3. Add the repo secrets: `OPENAI_COMPATIBLE_API_KEY` (your Nebius key), and `OPENWIKI_PR_TOKEN`, a fine-grained token with read/write on Contents and Pull requests.4. Keep the PR version rather than the auto-merge variant, so the docs get reviewed.
